# 한국사 Advanced RAG 발표 대본

## 1. 표지

안녕하세요. 모듈4 과제로 제작한 한국사 Advanced RAG 기반 AI 역사 사료 해설 시스템을
소개하겠습니다. 이 프로젝트는 역사 질문에 바로 답하는 챗봇보다, 답변의 근거가 되는 사료를
찾고 직접 인용과 출처를 검증하는 연구 보조 도구에 가깝습니다.

## 2. 개발 배경 및 문제 정의

역사학을 공부하며 레포트를 작성할 때 가장 많은 시간이 드는 과정은 사료를 찾고, 원문에서
해당 문장이 실제로 존재하는지 다시 확인하는 일이었습니다. 일반 LLM은 설명을 빠르게 만들지만
근거가 불명확하거나 그럴듯한 내용을 섞을 수 있습니다. 그래서 검색 결과와 직접 인용을 끝까지
추적하는 시스템을 만들었습니다.

## 3. 프로젝트 목표

목표는 네 가지입니다. 한국사 사료를 한곳에서 검색하고, 검색된 사료만으로 해설하며, 직접
인용과 출처를 확인하고, 비전공자도 사용할 수 있는 웹 화면으로 제공하는 것입니다. 근거가
부족한 경우에는 답을 억지로 완성하지 않고 추가 검토가 필요하다고 알려 주도록 설계했습니다.

## 4. 기술 스택 및 개발 환경

Python과 LangChain이 전체 흐름을 연결하고 Streamlit이 사용자 화면을 담당합니다. Gemini는
질문 변환과 검색 도구 선택, 리랭킹을 맡습니다. GPT는 선택된 사료를 바탕으로 해설을 만들고
다시 검증합니다. Pinecone은 3,072차원의 Dense 벡터를 cosine 방식으로 검색합니다.

## 5. Advanced RAG 시스템 아키텍처

사용자 질문은 먼저 Gemini에서 검색에 적합한 질의로 바뀝니다. 이후 Pinecone과 필요할 때 공식
사료를 검색합니다. Gemini가 관련 문서를 다시 고르고, GPT가 해설을 생성합니다. 마지막에는
GPT의 의미 검증과 Python의 출처 ID 및 인용문 문자열 검사를 함께 수행합니다. 각 단계의 결과는
다음 단계로 실제 전달됩니다.

## 6. 역사 사료 데이터 및 벡터 검색

고대부터 근현대까지 14개 데이터 그룹을 준비했습니다. 원문 기사 67,357개를 검색에 적합한
68,150개 청크로 만들었습니다. OpenAI의 text-embedding-3-large로 3,072차원 벡터를 생성해
Pinecone의 하나의 네임스페이스에 적재했습니다. 데이터가 많다는 사실과 모든 질문에 충분한
근거가 있다는 사실은 다르므로, 검색 결과가 없을 때는 근거 부족으로 처리합니다.

## 7. Gemini 기반 Tool Calling

Tool Calling은 모델이 직접 외부 사이트를 조작하는 방식이 아닙니다. Gemini가 어떤 검색 함수가
필요한지 요청하면 Python이 허용된 함수를 실행하고 결과를 돌려줍니다. 기본 검색은 Pinecone을
사용합니다. 연도나 날짜 근거가 부족하고 조선왕조실록에서 확인할 수 있을 때만 공식 검색을
추가합니다. 전체 도구 호출은 두 번으로 제한했습니다.

## 8. GPT 기반 역사 사료 해설 및 검증

GPT는 핵심 답변, 사료 내용, 역사적 맥락, 역사적 의미, 해석의 한계 순서로 설명합니다. 그러나
길게 설명하는 것보다 근거를 지키는 것이 우선입니다. 직접 인용은 실제 원문 문자열과 일치해야
하며, 출처 ID가 없거나 문장부호가 달라진 인용은 차단합니다. 화면에서는 내부 ID를 번호형
인용으로 바꾸어 보여 줍니다.

## 9. Streamlit 구현 화면 및 실제 시연

이 화면은 실제 Streamlit 실행 결과입니다. 질문은 훈민정음의 창제와 반포 시기, 그리고 이를
확인할 수 있는 사료를 함께 물었습니다. 시스템은 『세종실록』 세종 25년 12월 30일 기사에서
창제 관련 기록을 찾았습니다. 그러나 이 날짜는 기사가 기록된 날짜이므로 실제 창제일을
12월 30일이라고 단정하지 않았습니다. 출처 화면에서는 공식 기사 URL과 기록 날짜, 원문 정보를
확인할 수 있습니다. 1446년 반포는 역사적으로 알려진 내용이지만, 이번 실행에서 그 사실을
뒷받침할 공식 검색 결과는 확보하지 못했습니다. 따라서 발표에서도 ‘역사적 사실’과 ‘이번
시스템이 검증한 결과’를 구분해서 설명하겠습니다.

## 10. 구현 결과와 테스트

실행 기록을 보면 Gemini가 Pinecone 검색과 공식 조선왕조실록 검색 도구를 모두 요청했고,
Python이 두 함수를 실제로 실행했습니다. Pinecone에서는 12건을 찾았지만 공식 검색 결과는
0건이었습니다. 그래서 질의 변환, 리랭킹, 해설 생성까지 완료된 뒤에도 최종 검증 상태는
`needs_review`로 남았습니다. 이것은 시스템 오류가 아니라, 반포 시기를 입증할 근거가 부족하다는
판정입니다. 최종 단위 테스트 59개는 코드 흐름이 의도대로 작동하는지 확인한 결과이며 역사적
사실의 정확성을 100퍼센트 보장한다는 뜻은 아닙니다.

## 11. 한계 및 향후 개선 방향

현재 공식 실시간 검색은 조선왕조실록 한 곳에 집중되어 있습니다. 데이터에 포함된 시대와 문헌의
밀도도 균일하지 않아 질문에 따라 검색 품질이 달라집니다. 복수 사건을 한 번에 묻는 질문은 각
사건의 근거를 따로 확보해야 합니다. 앞으로 공식 검색 범위를 넓히고 인용 검증과 해설 품질을
지속적으로 개선할 수 있습니다.

## 12. 결론

이 프로젝트를 통해 수업에서 배운 Advanced RAG와 Tool Calling을 실제 역사 연구 문제에
적용했습니다. 가장 중요한 성과는 답변을 길게 만드는 것이 아니라, 어떤 사료를 사용했고 무엇을
확인하지 못했는지 보여 주는 구조를 완성한 것입니다. GitHub에서 코드와 검증 자료를 확인할 수
있고 Streamlit에서 실제 서비스를 실행할 수 있습니다. 감사합니다.
